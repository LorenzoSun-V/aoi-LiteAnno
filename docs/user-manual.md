# aoi-LiteAnno 使用手册

aoi-LiteAnno 是一个轻量的图片标注工具，标注文件与 X-AnyLabeling 的 JSON 格式兼容：用 X-AnyLabeling 标过的图片可以直接接着标，标完的文件 X-AnyLabeling 也能打开。程序里不加载模型，也不做自动标注。

本手册分三部分，按需要阅读：

- [第一部分：标注人员](#第一部分标注人员)：打开图片、画框、确认、快捷键。
- [第二部分：现场部署人员](#第二部分现场部署人员)：放置程序、数据存放、换 Logo、常见问题。
- [第三部分：算法工程师](#第三部分算法工程师)：项目文件、导入导出、姿态配置、命令行。

---

## 第一部分：标注人员

### 1. 打开图片文件夹

双击 `LiteAnno.exe`，用“文件 > 打开文件夹…”（Ctrl+U）选择放图片的文件夹。左边列出文件夹（含子文件夹）里的全部图片，右边是形状列表和“选中形状”面板，中间是图片。

文件夹分两种，打开方式一样：

- **普通图片文件夹**：没有 `liteanno` 子文件夹。和 X-AnyLabeling 一样直接标：类别名可以自由填写，所有画图工具都能用。程序只在每张图片旁边写同名的 `.json` 标注文件，不写别的东西。
- **项目文件夹**：有 `liteanno/project.json`（工程师准备的项目文件）。类别、能用的形状、图片级标签都按项目文件来，图片按批次分给你标。

标注文件随时自动保存：切换图片、停顿一会儿都会保存。状态栏右边显示“已保存”“保存中…”或“有未保存的修改”。也可以按 Ctrl+S 立即保存。

### 2. 画形状

在工具栏选工具，或按快捷键：

| 工具 | 快捷键 | 怎么画 |
| --- | --- | --- |
| 选择 | Ctrl+J | 点选形状，拖动移动形状或顶点 |
| 矩形 | R | **点两下**：点一个角，再点对角；或按住拖出来 |
| 多边形 | P | 逐个点顶点；点回第一个点、双击或按回车结束 |
| 旋转框 | O | 和矩形一样点两个角或拖出，画好后再转角度 |
| 点 | Shift+P | 点一下 |
| 线段 | Shift+L | 点两下（起点、终点），或拖出来 |
| 折线 | Shift+S | 和多边形一样逐点点，双击或回车结束 |
| 圆 | Shift+C | 点圆心再点圆周上一点，或从圆心拖出来 |

画的过程中：

- Esc 取消正在画的形状。
- 画多边形、折线时，退格键或 Ctrl+Z 删掉最后一个点。
- 画完会弹出类别对话框，选择或输入类别。

“点两下”是指按下后在原地松开算一次点击；按住鼠标移动再松开就是拖出来。两种方式都可以，按自己习惯。

项目文件夹里只有项目允许的工具可用，其余工具是灰的。

### 3. 修改形状

先用选择工具（Ctrl+J）选中形状：

| 操作 | 方法 |
| --- | --- |
| 移动形状 | 拖动形状内部；或按方向键，每次 1 像素 |
| 移动顶点 | 拖动顶点 |
| 改类别 | 双击形状，或 Ctrl+E，或在右边“选中形状”面板里选 |
| 改矩形位置和大小 | 在“选中形状”面板里填 x、y、w、h，按回车 |
| 改组号 | 在“选中形状”面板的“组号”里填数字，按回车；清空表示没有组 |
| 旋转旋转框 | Z / V 转 1°，X / C 转 0.1° |
| 删除 | Delete |
| 复制、粘贴 | Ctrl+C、Ctrl+V（粘贴在原位置，可以复制到下一张图） |
| 撤销、重做 | Ctrl+Z、Ctrl+Shift+Z |

**组号**用来把属于同一个目标的几个形状连起来，例如姿态标注里一个人的框和他的各个关键点。在一个矩形里面画点时，程序会自动把点和这个矩形配成同一组（矩形还没有组号时，自动给它一个没用过的编号），一般不用手动填。

### 4. 右键菜单

在图片上点右键（不拖动），会选中鼠标下的形状并弹出菜单，里面有：确认并下一张、确认当前图片、跳过、改类别、复制、粘贴、隐藏、删除、各个画图工具、撤销、重做。菜单里每一项后面写着它的快捷键。

在图片上按住右键或中键拖动是平移图片，松开时不会弹出菜单。

### 5. 看图

| 操作 | 方法 |
| --- | --- |
| 缩放 | Ctrl + 滚轮；或 Ctrl++、Ctrl+- |
| 原始大小 | Ctrl+= |
| 适合窗口 | Ctrl+F |
| 平移 | 滚轮上下滚；按住空格再用左键拖；或用右键、中键拖 |
| 隐藏选中的形状 | S（下一张图会重新显示） |
| 显示上一个隐藏的形状 | W |
| 显示或隐藏全部形状 | Ctrl+H |
| 显示或隐藏类别文字 | Ctrl+L（类别文字太大挡住小框时用） |

### 6. 确认和跳过

每张图标完后要**确认**，表示你已经看过这张图、标注正确。

- **F：确认并下一张**。最常用，左手按 F，右手用鼠标。
- **E：跳过**。图片看不清、不该标等情况，必须填写跳过原因。
- Ctrl+Alt+K：只确认当前图片，不翻页。
- A / D：上一张、下一张（不确认）。
- Ctrl+Shift+D / Ctrl+Shift+A：下一张、上一张未完成的图片。

注意：

- **按住 F 不会连续确认**。每张图要单独按一次，防止没看过的图被确认。
- 图片里没有任何目标时，按钮显示“确认无目标”，确认后这张图在导出时作为负样本。
- 改动已确认的图片后，它会变回“待确认”，需要重新确认。
- 不满足确认条件时不能确认，会提示原因，例如类别不在项目的类别列表里、形状面积为 0、标注文件里的图片尺寸与图片不一致。
- 跳过的图片可以用“取消跳过”恢复。
- 项目设置了图片级标签（如 OK / NG）时，右边有“图片级标签”面板，单选时必须选中一项才能确认。

按 F1 可以随时查看全部快捷键。

### 7. 图片状态

左边图片列表里每张图后面有状态：

| 状态 | 含义 |
| --- | --- |
| 未处理 | 还没有标注 |
| 待确认 | 有标注，还没确认（包括导入的、别人预标的） |
| 已确认 | 已确认且满足确认条件，算完成 |
| 已跳过 | 已跳过并写了原因，算完成 |
| 已确认但有问题 | 文件里写了已确认，但不满足确认条件（例如外部脚本写的），需要检查后重新确认 |
| 状态冲突 | 同时是确认和跳过，或跳过没有原因；重新确认或跳过即可 |
| 标注文件损坏 | JSON 文件读不了，交给工程师处理 |
| 名称冲突 | 同一文件夹里有主文件名相同的图片（如 `a.jpg` 和 `a.png`），只读，交给工程师处理 |
| 缺失 | 批次里有这张图，但图片文件不在了 |

### 8. 批次（只在项目文件夹里）

项目文件夹里的图片按固定数量分批（默认每批 1000 张），每次标一批：

- 打开项目时自动回到上次的批次。
- “批次 > 开始下一批”：分出下一批新图片。
- “批次 > 选择批次…”：换到别的批次。
- “批次 > 查看未完成项”：列出这批里还没完成的图片。
- “批次 > 显示全部图片”：不按批次，显示全部。

| Shift+P / Shift+L / Shift+S / Shift+C | 点 / 线段 / 折线 / 圆 |

## 第二部分：现场部署人员

### 10. 放置程序

测试版只有一个文件 `LiteAnno.exe`，旁边不需要任何文件，可以放在任意文件夹或 U 盘里直接运行，不用安装。支持 Windows 10、Windows 11 64 位。

### 11. 数据放在哪里

- 图片放在本机硬盘上效果最好。也可以直接打开 U 盘里的文件夹标注，但标注过程中不要拔 U 盘。
- 标注文件（`.json`）写在每张图片旁边，和图片同名。
- 程序还在本机当前用户的目录（`%LOCALAPPDATA%\LiteAnno`）里存两样东西，它们只在这台电脑上，不会跟着 U 盘或数据文件夹走：
  - **目录索引**：加快大文件夹的打开速度。只是缓存，删掉会自动重建。
  - **恢复记录**：标注文件写入失败（例如 U 盘被拔、磁盘满）时，没写进去的修改存在这里。它可能是这些修改**唯一的副本**，**不要手动删除**。下次在这台电脑上打开同一个文件夹会提示恢复，也可以用“文件 > 处理未写入的编辑…”恢复或明确放弃。
- 在同一台电脑、同一个 Windows 用户下，一个文件夹同一时间只能被一个本程序窗口（或命令行工具）打开。这个限制管不到别的电脑，也管不到其他程序和脚本：不要让两台电脑同时标同一个文件夹。

### 12. 遇到提示怎么办

| 提示 | 处理 |
| --- | --- |
| 标注文件被其他程序修改 | 别的程序（或别的电脑）改了这张图的标注。选“重新加载”放弃自己的修改，或“用我的版本覆盖” |
| 保存失败 | 检查磁盘空间、U 盘是否插好、文件是否只读，解决后按 Ctrl+S 再保存。没写进去的修改一般已存进恢复记录；如果连恢复记录也写不进去，修改只在程序里，这时不要直接关程序，先解决问题再保存，关闭时按提示处理 |
| 项目已经在别处打开 | 这台电脑上还有一个本程序窗口（或命令行工具）开着这个文件夹，先关掉它。别的电脑上打开的窗口不会引起这个提示 |
| 项目文件有错误 | `liteanno/project.json` 写错了，提示里会写出错的字段，交给工程师改 |
| 名称冲突 | 同一文件夹里有 `a.jpg` 和 `a.png` 这样主文件名相同的图片，它们会共用 `a.json`，所以只读。请改名其中一张 |

### 13. 更换程序 Logo

程序只用一个 Logo 文件：仓库里的 `branding/logo.png`。窗口左上角、任务栏、“帮助 > 关于”和 exe 文件图标都由它生成。

1. 准备一张 PNG 图片，最好是正方形，边长至少 256 像素（建议 512），背景可以透明。不是正方形也可以，不会被拉伸。
2. 用它替换仓库里的 `branding/logo.png`（文件名不变），提交并推送到 GitHub。
3. 在 GitHub 的 Actions 里运行 **Package** 工作流（分支选 main），下载新的 exe。

注意：

- 必须是 `.png` 文件。
- 小图标（16、24 像素）是从大图缩出来的，Logo 最好简单、对比鲜明。
- 换了 Logo 后 exe 文件图标没变，是 Windows 资源管理器的图标缓存：把 exe 改个名字，或重启资源管理器。

自己编译的做法见 [branding/README.md](../branding/README.md)。

## 第三部分：算法工程师

### 14. 项目文件 `liteanno/project.json`

有项目文件的文件夹按项目标注。可以用命令行 `liteanno-cli init` 创建（见第 19 节），也可以用自己的脚本生成：

```json
{
  "formatVersion": "1.0",
  "projectId": "3f6c2a9e-8b1d-4c57-9a0e-2d4b7f1e6c33",
  "name": "A 线外观缺陷 2026-10",
  "shapeTypes": ["rectangle", "polygon"],
  "classes": [
    {"id": 0, "name": "scratch", "color": "#E53935"},
    {"id": 1, "name": "dent", "color": "#1E88E5"}
  ],
  "imageLabels": {"mode": "single", "options": ["OK", "NG"]},
  "batchSize": 1000
}
```

| 字段 | 说明 |
| --- | --- |
| `formatVersion` | 必填，`"1.0"` |
| `projectId` | 必填，UUID，创建后不要改 |
| `name` | 显示名称 |
| `shapeTypes` | 允许的形状：`rectangle`、`rotation`、`polygon`、`point`、`line`、`linestrip`、`circle`；不写表示不标形状（只做图片级分类） |
| `classes` | 类别：`id` 是导出时的类别编号（不重复的非负整数），`name` 是写进标注的类别名，`color` 可选 |
| `imageLabels` | 图片级标签：`mode` 为 `single`（单选）或 `multi`（多选），`options` 是选项 |
| `batchSize` | 每批图片数，默认 1000 |

项目文件写错时程序拒绝打开，并指出出错的字段。类别的 `id` 一旦用于导出就不要改变含义。

### 15. 预标注与确认

可以用自己的模型生成 X-AnyLabeling 格式的 JSON 放在图片旁边作为预标注，`checked` 写 `false`。标注人员打开后看到的是“待确认”，逐张检查、修改后按 F 确认。

`checked` 表示**有人看过并确认了这张图**。格式、几何和类别检查通过，不能证明没有错标、漏标，所以不要用脚本批量把 `checked` 写成 `true`，程序和命令行也都没有批量确认功能。

### 16. 导出

“文件 > 导出…”，选择格式、范围（当前批次或整个项目）和导出文件夹。

| 格式 | 内容 |
| --- | --- |
| YOLO 检测 | 矩形 |
| YOLO 分割 | 多边形 |
| YOLO 旋转框（OBB） | 旋转框 |
| YOLO 姿态 | 矩形和关键点，需要姿态配置文件（第 18 节） |
| VOC | 矩形；或矩形和多边形 |
| COCO 检测 / 实例分割 | 矩形 / 多边形 |
| COCO 关键点 | 矩形和关键点，需要姿态配置文件 |
| DOTA | 旋转框 |
| 掩膜 PNG | 多边形，灰度图，类别值 = 类别编号 + 1，另写 `mask_colors.json` |
| LabelMe | 全部形状，附图片 |
| 图片分类 | 按图片级标签 |

规则：

- **导出哪些图片**：项目文件夹只导出已确认的图片，已确认且没有目标的图片导出为负样本（如 YOLO 的空 txt）。普通文件夹导出有标注的图片（不要求确认，但要满足确认条件），跳过的图片不导出。
- **类别编号**：只有 YOLO（检测、分割、旋转框）、COCO 检测、COCO 实例分割和掩膜需要类别编号；VOC、DOTA、LabelMe、图片分类直接写类别名，姿态格式按姿态配置文件编号。编号来源如下：

  | 格式 | 没选 `classes.txt`（用项目的类别） | 选了 `classes.txt`（普通文件夹必须选） |
  | --- | --- | --- |
  | YOLO 检测 / 分割 / 旋转框 | 项目的 `classes[].id` | 行号，第一行是 0 |
  | 掩膜 PNG | 像素值 = `classes[].id` + 1，背景 0 | 像素值 = 行号 + 1，背景 0 |
  | COCO 检测 | 项目的 `classes[].id` | 行号 + 1，第一行是 1（与 X-AnyLabeling 相同） |
  | COCO 实例分割 | 项目的 `classes[].id` | 最前面加 `_background_` 作为 0，第一行是 1；文件第一行是 `__ignore__` 时去掉它，已经以 `_background_` 开头时不再加（与 X-AnyLabeling 相同） |
  | YOLO 姿态 | 姿态配置文件里类别的顺序，第一个是 0（不看项目 id 和 `classes.txt`） | 同左 |
  | COCO 关键点 | 姿态配置文件里类别的顺序，第一个是 1 | 同左 |

  项目有类别又选了 `classes.txt` 时，以 `classes.txt` 为准。
- **导出文件夹**必须是新的或空的，并且不能在数据文件夹里面。
- **不会悄悄丢对象**：有对象无法转换成所选格式时（例如导出 YOLO 检测时有多边形、类别不在列表里），默认整个导出不写，列出原因；可以选“跳过这些图片继续导出”。
- 导出文件夹里会写一份 `liteanno-export.json`，记录导出了哪些图片、跳过了哪些、为什么。
- 结果与 X-AnyLabeling 4.2.0 的导出一致（CI 里逐项对照）。有意不同的地方：YOLO、VOC 保留子文件夹结构，COCO 的 `file_name` 写相对路径，用项目类别导出 COCO 时类别 id 直接用 `classes[].id`（不像上游那样加 1）；旋转框有角超出图片时导出 OBB/DOTA 按无法转换处理（上游会悄悄丢掉）。

### 17. 导入

“文件 > 导入…”，把外部标注转成每张图片旁边的 JSON。支持的格式与导出相同（LabelMe 和图片分类除外）。

- **配对**：标注文件按图片的相对路径配对（`sub/a.jpg` 对 `标注文件夹/sub/a.txt`），找不到时再按文件名在标注文件夹顶层找。同一个文件名对应多张图片时不导入，列出原因。COCO 是一个 `.json` 文件，按 `file_name` 配对。
- **类别**：YOLO 的类别编号先按选的 `classes.txt` 换成名称，没选就用标注文件夹里的 `classes.txt`，再没有就用项目的类别。
- **已有标注的图片**：默认不动，只导入还没有标注的图片；也可以选“追加在原有形状后面”或“替换原有形状”。追加时组号会自动避开已有的组号。
- **导入的图片都是“待确认”**，需要逐张检查后确认。
- **先检查后写入**：有标注文件无法导入（格式错误、类别不认识、尺寸和图片不一致、坐标数值太大换算后溢出等）时，默认整个导入不写任何文件；可以选择跳过这些图片继续。
- 坐标落在图片边界外但是正常数字的，照常导入，不会被拒绝。
- 窗口里有未写入修改的图片、只读文件、名称冲突的图片不写，列在报告里。
- 掩膜只接受 PNG（JPEG 有损压缩会改变类别值），需要 `mask_colors.json`（本程序导出掩膜时会写）。

### 18. 姿态（关键点）配置文件

YOLO 姿态和 COCO 关键点需要知道每个类别有哪些关键点、顺序如何。和 X-AnyLabeling 一样，用一个 YAML 文件说明，在导出、导入对话框的“姿态配置”里选择：

```yaml
has_visible: true
classes:
  person:
    - nose
    - left_eye
    - right_eye
  car: [front, back]
```

- `classes` 下每个类别列出它的关键点名称，顺序就是导出文件里的顺序；类别的顺序就是 YOLO 的类别编号（第一个是 0）。
- `has_visible`：导出文件里是否每个关键点带可见性（0 缺失，1 遮挡，2 可见）。不写时为 `true`。
- 名称是数字或 `yes`、`no`、`true` 之类时要加引号，例如 `- "1"`。

在程序里怎么标一个姿态目标：

1. 用矩形工具框出目标，类别选配置里的类别（如 `person`）。
2. 用点工具（Shift+P）在框里点各个关键点，类别选关键点名称（如 `nose`）。点在框里时自动和框同组。
3. 没标的关键点导出为缺失（`0 0 0`）。

可见性：导出时关键点写为可见（2），标注文件里 `difficult` 为 true 的点写为遮挡（1）。程序里暂时没有标记遮挡的开关，导入时可见性为 1 的点会记为 `difficult`，导出时保持不变。

导出检查：每个组必须有且只有一个配置里的类别的矩形，组里的点必须是这个类别的关键点名称，且每个名称最多一次；不满足的图片按无法转换处理。导出时会在导出文件夹里写一份 `pose_config.yaml`。

与 X-AnyLabeling 有意不同的两处：

- YOLO 姿态带可见性时，位于 (0, 0) 且可见性为 1 或 2 的关键点会保留（X-AnyLabeling 导入时会丢掉，本程序自己导出的 `0 0 2` 就读不回来）。
- COCO 关键点导出的 `ignore` 用矩形自己的 `difficult`（X-AnyLabeling 取的是图片最后一个形状的）。

### 19. 命令行工具（仅工程师）

`liteanno-cli.exe` 不随测试版发出，需要时按仓库 README 自己编译。它和窗口程序用同一把文件夹锁，窗口正打开某个文件夹时，命令行不会改它。

```
liteanno-cli init   <数据文件夹> --name <名称> --classes scratch,dent --shape-types rectangle,polygon [--batch-size 1000]
liteanno-cli status <数据文件夹> [--batch b000003]
liteanno-cli export <数据文件夹> --format <格式> --out <导出文件夹> [选项]
liteanno-cli import <数据文件夹> --format <格式> --labels <标注文件夹或 COCO 文件> [选项]
```

| 命令 | 作用 |
| --- | --- |
| `init` | 创建项目文件 `liteanno/project.json`。类别按逗号分隔，编号从 0 开始。已有项目文件或本机还有未处理的恢复记录时拒绝 |
| `status` | 统计各状态的图片数量 |
| `export` | 导出，规则同第 16 节 |
| `import` | 导入，规则同第 17 节 |

常用选项：

| 选项 | 说明 |
| --- | --- |
| `--format` | 导出：`yolo-det`、`yolo-seg`、`yolo-obb`、`voc`、`voc-polygon`、`coco-det`、`coco-seg`、`dota`、`mask`、`yolo-pose`、`coco-pose`、`labelme`、`classify`；导入：除 `labelme`、`classify` 外同上 |
| `--batch` | 只处理这个批次（如 `b000003`），可以写多次 |
| `--out` | 导出文件夹，必须是新的或空的 |
| `--copy-images` | 导出时同时复制图片 |
| `--classes-file` | 类别文件 `classes.txt` |
| `--pose-config` | 姿态配置文件 `.yaml`（`yolo-pose`、`coco-pose`） |
| `--labels` | 导入的标注文件夹；COCO 是 `.json` 文件 |
| `--mapping` | 导入掩膜的映射文件，默认标注文件夹或上一级的 `mask_colors.json` |
| `--mode` | 导入时已有标注的图片：`new` 不动（默认）、`append` 追加、`replace` 替换 |
| `--skip-unconvertible` | 跳过无法转换的图片，继续处理其余图片 |
| `--licenses`、`--license <名称>` | 显示授权说明和许可证全文 |

命令行**没有批量确认**：确认只能由人在窗口里逐张做（见第 15 节）。

返回值：成功为 0，出错时非 0，原因打印在标准错误输出里。
